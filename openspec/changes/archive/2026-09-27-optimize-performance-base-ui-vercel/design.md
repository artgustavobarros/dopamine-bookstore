# Design: Performance Optimization, Base UI Migration, and Vercel Deployment

## Context

The Dopamine Bookstore application is built with React 19, TanStack Start (isomorphic Vite SSR), Tailwind CSS v4, Zustand, and TanStack Query. An investigation revealed opportunities to optimize performance and execution time:
- Over 26 font files (~500kB) generated by static Fontsource weights.
- `axios` loaded as a heavy runtime dependency (~35kB) for two GET requests, while `viacep.ts` already uses native `fetch`.
- Dead components (`radio-group.tsx`, `select.tsx`) and ghost packages (`next-themes`, `@openrouter/sdk` in workspace permissions).
- Primitive UI components (`Sheet`, `Button`) still tethered to `radix-ui`, which the user requested to modernize to Base UI (`@base-ui-components/react`).
- Absence of Nitro adapter and `vercel.json` required for TanStack Start SSR deployment to Vercel Functions.

## Goals / Non-Goals

**Goals:**
- Replace Radix UI with `@base-ui-components/react` for `Button` and `Sheet`.
- Purge dead code and remove `axios`, `next-themes`, and unnecessary runtime dependencies.
- Consolidate fonts using `@fontsource-variable/work-sans` and `.woff2` modern subsets.
- Configure `nitro` in `vite.config.ts` and provide `vercel.json` for zero-config Vercel deployment.
- Maintain 100% test pass rate across all 25 Playwright E2E tests.

**Non-Goals:**
- Rewriting the application as a client-side SPA (TanStack Start SSR is retained to protect `GEMINI_API_KEY` on the server).
- Redesigning visual layouts or color schemes (neobrutalist identity remains intact).

## Decisions

### 1. Base UI for Drawer (Sheet) and Button
- **Choice**: Use `@base-ui-components/react/dialog` for `Sheet` and custom composable slot/render for `Button`.
- **Rationale**: Base UI is unstyled, lightweight, and developed by the MUI/Floating UI teams. It eliminates the multi-package Radix footprint and aligns with the latest shadcn primitives.

### 2. Native Fetch over Axios
- **Choice**: Refactor `src/lib/open-library.ts` to use `fetch` with `AbortSignal` and query string parameters.
- **Rationale**: Node 18+ and modern evergreen browsers support `fetch` natively. Axios adds redundant bundle weight without added functionality for simple GET requests.

### 3. Font Optimization via Variable Font
- **Choice**: Use `@fontsource-variable/work-sans` for body text and restrict imports to `.woff2` Latin subsets.
- **Rationale**: Replaces 8 static files (weights 400, 500, 600, 700 in latin and latin-ext) with 1 unified variable font file, reducing initial asset requests significantly.

### 4. Vercel Deployment via Nitro Adapter
- **Choice**: Add `nitro` and `nitro()` plugin in `vite.config.ts`, along with `vercel.json`.
- **Rationale**: TanStack Start compiles isomorphic server functions into Vercel Serverless Functions via Nitro. This keeps `GEMINI_API_KEY` secure in the server environment while allowing Vercel Edge CDN to serve static assets.

## Risks / Trade-offs

- **[Risk] Base UI Dialog markup differs slightly from Radix Dialog** → Mitigation: Keep the exact same CSS classes, data attributes, and test locators (`role="dialog"`, ARIA labels, close buttons) to avoid breaking UI or Playwright tests.
- **[Risk] Font swap causes CLS (Cumulative Layout Shift)** → Mitigation: Retain standard CSS fallback fonts (`sans-serif`, `monospace`) and font-display swap.
- **[Risk] Nitro build changes output directory** → Mitigation: Verify local `pnpm build` and ensure dev and test scripts continue functioning.
